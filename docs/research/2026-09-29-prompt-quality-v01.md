# 사주 풀이의 정확성과 쉬운 말: 프롬프트 조사 v01

조사일: 2026-09-29. 이 문서는 설계 제안이며 서비스 코드와 실제 생성 문장은 변경하지 않았다.

## 현재 서비스에서 확인한 점

- 사주 원국·대운·귀인은 `lib/saju`가 계산하고, 선택형 Gemini는 그 계산 자료를 받아 글을 쓴다. 따라서 프롬프트는 계산 오류를 고치는 수단이 아니라 **계산 자료를 틀리지 않게 인용하고 쉽게 설명하는 수단**이다.
- 공통 프롬프트 `lib/saju/reading-prompt.ts`와 종합 해석 프롬프트 `lib/saju/gemini-reading.ts`는 쉬운 말도 요구하지만, 거의 모든 항목에서 전문 근거 둘 이상과 긴 분량을 함께 요구한다. 초심자에게는 근거가 본문을 밀어내기 쉽다.
- API는 JSON 형식과 코드 검증을 이미 사용한다. 이는 유지해야 한다. JSON 형식이 맞아도 내용이 계산과 맞는다는 보장은 없으므로 현재의 의미 검증도 계속 필요하다.
- `app/api/reading/route.ts`는 Gemini 3.5 Flash-Lite 요청에 `temperature: 0.45`를 지정한다. Google의 최신 Gemini 3.x 안내는 기본 샘플링 설정을 권한다. 변경이 더 낫다는 보장은 없으므로 같은 사례에서 비교해야 한다.
- 현재 **생활 운** 본문은 Gemini가 아닌 `lib/saju/fortune-domains.ts`의 문장 양식으로 생성된다. AI 프롬프트 개선만으로 이 화면의 전문 용어는 사라지지 않는다.

## 조사 결과와 이 서비스에 맞는 방향

1. **짧은 공통 지시 + 화면별 과제**. Google은 Gemini 3 계열에 명확하고 간결한 지시, 일관된 구획, 핵심 제약의 우선 배치를 권한다. 공통 부분에는 계산 자료만 쓰기·없는 사건 만들지 않기·독자에게 쉬운 말 쓰기만 두고, 대운/연운/월운별 정확한 규칙은 해당 과제에 둔다. [Gemini 3.5 안내](https://ai.google.dev/gemini-api/docs/whats-new-gemini-3.5), [프롬프트 설계](https://ai.google.dev/gemini-api/docs/prompting-strategies)
2. **서로 다른 가상 사례 2~3개**. 하나는 좋은 풀이, 하나는 전문어가 과한 풀이를 고친 예시, 하나는 계산 근거가 부족할 때 내용을 꾸며내지 않는 예시로 사용한다. 실제 방문자의 출생 정보는 예시에 쓰지 않는다. 예시는 형식과 말투를 보여 주되, 모든 사주에 같은 문장을 복사하지 않도록 한다. [프롬프트 설계](https://ai.google.dev/gemini-api/docs/prompting-strategies)
3. **생활 문장과 근거의 순서 분리**. 첫 두 문장은 일·돈·관계처럼 이용자가 바로 이해할 생활 언어로 쓴다. 이후 필요한 계산 근거만 짧게 붙인다. 이는 공식 문서의 출력 형식과 예시를 명확히 하라는 원칙을 이 서비스의 읽기 문제에 적용한 **설계 제안**이다. 정확도 향상이 검증된 사주 전용 공식은 아니다. [프롬프트 설계](https://ai.google.dev/gemini-api/docs/prompting-strategies)
4. **코드 검증과 사람 비교 유지**. 구조화 출력은 JSON 모양을 돕지만 값의 의미가 맞는지 보장하지 않는다. 가상 원국을 고정해 현재안과 후보안을 나란히 생성하고, 계산 불일치·없는 개인사 추정·읽기 쉬움·반복·구체성을 평가한다. AI 평가는 사람의 판단과 대조한다. [구조화 출력](https://ai.google.dev/gemini-api/docs/structured-output), [평가 문서](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/models/evaluate-judge-model)

## 우선 시험할 프롬프트 초안

아래는 기존 JSON 응답 형식과 코드 검증을 유지한 채 **AI가 쓸 문장**에 적용할 초안이다. 실제 계산 자료는 요청 시 별도 구획에 넣는다.

```text
<역할>
당신은 계산된 사주 자료를 처음 보는 사람에게 설명하는 한국어 글쓴이입니다.
실제 상담 경력이나 이용자의 과거를 알고 있는 것처럼 말하지 마세요.
</역할>

<반드시 지킬 규칙>
제공된 계산 자료에 있는 관계와 시기만 사용하세요. 간지, 연도, 십성, 합·충을 새로 계산하거나 만들지 마세요.
자료에서 확인할 수 없는 개인 사건, 직업, 가족 사정과 미래 결과는 쓰지 마세요.
원국(타고난 바탕), 대운(긴 시기), 세운(선택한 해), 월운(그달)을 서로 바꿔 부르지 마세요.
근거가 부족하면 단정 대신 확인 가능한 범위의 풀이만 쓰세요.
</반드시 지킬 규칙>

<글쓰기>
각 항목의 첫 두 문장은 한자와 사주 용어 없이, 생활에서 나타날 수 있는 모습부터 설명하세요.
이어서 그 풀이를 뒷받침하는 계산 근거를 필요한 만큼만 한두 문장으로 연결하세요.
사주 용어를 꼭 써야 한다면 첫 등장에 일상적인 뜻을 바로 붙이세요.
장점과 부담이 달라지는 조건을 구체적으로 말하고, 같은 조언을 여러 항목에 반복하지 마세요.
도령의 차분한 존댓말을 쓰되 예언하거나 겁주지 마세요.
</글쓰기>

<계산 자료>
[서버가 계산하고 검증한 자료]
</계산 자료>

<이번 과제>
[예: 이번 사람의 2026년 흐름. 제공된 세운과 해당 대운을 구분해 설명]
기존 JSON 응답 형식의 모든 필드를 채우세요. 응답을 내기 전에 간지·연도·대운 구간이 제공 자료와 일치하는지 확인하세요.
</이번 과제>
```

## 비교 시험 기준

- 가상 입력 6~10개: 절기 경계, 윤달, 해외 시간대, 미성년, 대운 시작 전, 서로 다른 오행·십성 조합을 포함한다.
- **통과 우선 조건**: 간지·연도·대운/세운/월운 혼동 0건, 자료에 없는 개인 사건 0건, 필수 JSON 누락 0건.
- **품질 비교**: 첫 문장을 일반인이 이해하는지, 개인별 근거가 실제로 연결되는지, 항목 간 반복이 적은지, 불필요한 전문어가 줄었는지 사람이 같은 기준표로 비교한다.
- 요청 시간과 API 사용량도 기록한다. 프롬프트를 짧게 줄이거나 샘플링 설정을 바꾸는 효과는 실제 응답을 보기 전에는 단정하지 않는다.
- 실제 방문자의 사주나 저장 결과를 시험 데이터로 사용하지 않는다. 기존 저장 해석은 다시 생성하기 전까지 바뀌지 않는다.

## 적용 순서 제안

1. 현재 프롬프트와 위 초안을 동일한 가상 원국으로 비교한다.
2. 계산 정확성과 문장 품질이 모두 나아진 경우에만 Gemini 지시를 교체한다.
3. 별도로 `fortune-domains.ts` 등 코드가 직접 만드는 생활 운 문장을 쉬운 말로 다듬는다.
