# 018 사주 해석 기본 프롬프트 재설계

## 요청과 목표

- 이용자는 현재 사주 해석이 형식적이라고 느낀다. 공개된 프롬프트 설계 자료를 검토해, 계산된 개인 사주를 실제 판단 자료처럼 읽을 수 있는 기본 프롬프트로 바꾼다.
- 30년 경력 역술가의 상담 태도와 분석 깊이를 지향하되 실제 경력이나 확인하지 않은 삶의 사건을 사칭하지 않는다. 좋은 면과 부담을 함께 말하고 명리학을 모르는 사람도 이해할 수 있게 쓴다.

## 참고한 설계 자료

- 싱가포르 GovTech의 [Prompt Engineering Playbook](https://www.developer.tech.gov.sg/products/collections/data-science-and-artificial-intelligence/playbooks/prompt-engineering-playbook-beta-v3.pdf)의 CO-STAR: 맥락(Context), 목표(Objective), 문체(Style), 말투(Tone), 독자(Audience), 응답 형식(Response)을 구분한다. 틀은 글쓰기 구조이며 명리학의 정확성을 보증하지 않는다.
- Google의 [Gemini Prompt design strategies](https://ai.google.dev/gemini-api/docs/prompting-strategies): 명확한 지시, 필요한 맥락, 소수의 구체적 예시, 제약, 반복 평가를 적용한다. JSON 같은 복잡한 출력은 기존 Gemini 구조화 출력 기능을 계속 사용한다.

## 구현 범위

1. 종합 해석과 장별 상담에 공유되는 기본 지시를 정의한다. 계산된 자료만 근거로 쓰고, 원국과 대운·세운·월운의 층위를 구별한다.
2. 문단마다 `생활에서 드러날 수 있는 모습 → 실제 계산 근거 둘의 관계 → 강점과 부담 → 달라질 조건 → 확인 질문 또는 행동`을 따르게 한다. 가상 예시는 형식만 보여 주며 실제 이용자의 사실로 옮기지 않는다.
3. 한자·십성·용신 등은 처음 등장할 때 쉬운 말로 풀고, 용신 보류·강약 경계처럼 계산이 확정하지 않은 부분은 유보한다. 질병·혼인·수익·합격·사망 같은 사건을 예언하지 않는다.
4. 기존 응답 형식, 모델, 개인정보 동의, 로컬 해석과 저장 데이터 형식은 유지한다. 프롬프트 변경 이후 새로 생성하는 Gemini 해석에 적용한다.

## 실패와 검증

- 형식 누락이나 계산 근거와 맞지 않는 응답은 기존 검증과 한 차례 재시도로 처리하고, 실패를 가짜 결과로 대체하지 않는다.
- 가상 입력에서 프롬프트의 구조, 쉬운 용어 설명, 양면 평가, 불확실성, 가상 예시와 개인정보 비포함을 테스트한다.
- 타입 검사·관련 테스트·전체 테스트·빌드를 실행한다. 실제 Gemini 응답과 화면은 API 사용 가능 상태에서 따로 확인하며, 실행하지 않았다면 성공으로 기록하지 않는다.

## 결과와 검증 (2026-09-24)

- CO-STAR 여섯 항목과 근거·양면성·생활말·조건부 조언을 `lib/saju/reading-prompt.ts`의 공통 기준으로 구현하고, 종합 해석과 장별 상담 생성에 연결했다.
- 가상 입력 프롬프트에서 출생 날짜·시각·질문·도시·지역·시간대·경도가 포함되지 않음을 검사했다. 프롬프트 전용 관련 테스트 27개와 전체 160개, 타입 검사, 빌드가 통과했다. 로컬 페이지 HTTP 200을 확인했다.
- 2026-09-24 원격 `main`을 pull했으며 새 커밋은 없었다. 가상 출생 자료로 Gemini API를 두 번 호출했고 모두 HTTP 200, 열두 월운과 대운 열한 구간을 반환했다. 실제 이용자 자료는 사용하지 않았다.
- 첫 응답은 한자·십성으로 시작하고 직장 책임 장면을 여러 필드에 반복했다. 단일 직장 사례를 학습·공동 지출의 두 가상 예시로 바꾸고 종합·원국·평생·연운의 첫 문장을 생활말로 시작하도록 조정했다.
- 두 번째 응답은 종합·연운의 첫 문장과 항목별 주제가 개선됐으나, 원국에 ‘삶의 전반적인 여정’처럼 개인 근거가 약한 상투 문장이 남았다. 실제 문체 품질은 아직 완료 기준에 못 미쳐 상태를 미완료로 유지한다. 자동 테스트는 160개, 타입 검사와 빌드 통과. 참가자 화면 확인 전.
- 기존 저장 해석은 재생성 전까지 기존 문장으로 남는다. 가상 사례 두 번만 확인했으므로 다른 원국에서의 해석 품질은 아직 알 수 없다.
