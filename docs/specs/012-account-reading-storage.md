# 계정별 사주 결과 데이터베이스 저장

## 목적
로그인한 이용자가 여러 사주 결과를 저장하고 다른 기기에서 같은 계정으로 다시 읽고 삭제한다.

## 사용자 흐름
1. 비로그인 이용자는 현재처럼 계산·해석하고 브라우저에서 다시 연다.
2. 로그인 후 결과 제목을 입력하고 `계정에 저장`을 누른다. 출생 정보·계산·해석이 Supabase에 저장되며 본인만 볼 수 있음을 버튼 옆에 안내한다.
3. `내 사주 보관함`에서 최신순으로 목록을 보고 결과를 열거나 삭제한다. 목록은 20건씩 더 불러온다.
4. 저장 실패 시 현재 해석을 보존하고 재시도한다. 기존 결과는 덮어쓰지 않으며 달라진 해석은 별도 기록으로 저장한다. 같은 제목·결과를 다시 저장하면 중복 생성하지 않는다.
5. 서버에서 연 결과를 기기에 자동 복사하지 않는다. 로그아웃 시 화면에서 제거한다. 삭제는 확인 후 실행하며 계정 저장본과 브라우저 저장본이 별개임을 안내한다.

## 저장 구조
`public.saju_readings`: id UUID, user_id UUID(auth.users 참조/계정 삭제 시 연쇄 삭제), title(1~80자), fingerprint(SHA-256), payload(JSONB), created_at.
- payload: 기존 SavedSajuResult 버전 1(생일/달력/윤달/시각/출생지/대운 기준, 원국, 대운, 귀인, 해석), 선택한 운세 연도. 계산만 한 결과도 저장 가능.
- 해석 버전(readingVersion)과 해석 연도를 유지한다. 현재 모델은 서버 코드의 gemini-3.5-flash-lite이며 이전 결과의 생성 모델을 추정해 기록하지 않는다. 가져올 때 저장 형식을 검증하며 손상된 결과를 임의로 재계산해 덮어쓰지 않는다.
- 앱은 UTF-8 500,000바이트, DB는 JSONB 표현의 공백을 고려해 최대 512 KiB로 제한한다. 버전과 주요 필드 형태를 DB에서도 확인한다.
- UNIQUE(user_id, fingerprint), 목록 조회용 (user_id, created_at DESC, id DESC) 인덱스.

## 접근 권한과 보관
- 행 단위 권한 검사(RLS)를 활성화한다. authenticated 사용자만 본인 user_id 행의 조회·추가·삭제 가능. 수정 권한은 주지 않는다.
- 익명 조회·추가, 타인 user_id로 저장, 다른 계정의 조회·삭제는 차단한다. 관리자 키는 앱에 사용하지 않는다.
- 공개 공유 링크는 이번 구현에 포함하지 않는다. 이전 PRD의 공개 링크 목표는 별도 기능으로 남긴다.
- 이용자가 삭제하거나 계정을 삭제할 때까지 보관한다. 계정 탈퇴 화면과 백업에서의 완전 삭제 절차는 별도 범위다. 이번 삭제는 서비스의 저장 행 삭제다.

## 완료 조건
- Spec 011 로그인 후 저장·조회·복원·삭제 및 다른 계정 차단을 검증한다.
- 실패 시 성공 문구를 표시하지 않는다. 로컬 결과가 지워지지 않는다.
- 이전 브라우저 결과를 사용자 조작 없이 업로드하지 않는다.
- 데이터베이스 권한은 가상 데이터와 트랜잭션 롤백으로 확인한다. 실제 사용자의 결과는 테스트에 업로드하지 않는다.

## 검증 상태
구현 및 DB 권한 검증 완료. 실제 로그인 계정의 화면 검증 대기.
- 원래 설정된 Supabase 프로젝트에 테이블·RLS·인덱스·제약조건을 migration으로 적용했다.
- 비구현 서브에이전트가 저장 기능 15개 및 대운 0번 없는 정상 자료 복원 회귀1개를 추가했다. 실제 폼을 실행해 계정 전환과 지연 응답을 확인하는 3개 검사도 추가했다. 최종 전체 93개·타입 검사·빌드 통과.
- `scripts/verify-account-rls.sql`을 실제 DB에서 실행해 가상 계정의 본인 저장/조회/삭제, 타인 조회/삽입/삭제 차단, 익명 접근 차단, 수정 금지와 JSON 형식 제한을 검증했다. 전체 테스트 트랜잭션은 롤백해 계정·결과를 남기지 않았다.
- 보안 검사에서 기존 내부 이벤트 함수의 불필요한 공개 실행 권한을 발견해 회수했다. 재검사 경고 0건.
- 참가자의 출생 정보/사주 결과는 검증 과정에서 서버에 업로드하지 않았다. 실제 Google 로그인 후 저장·다른 기기 복원은 참가자 확인 전이다.
