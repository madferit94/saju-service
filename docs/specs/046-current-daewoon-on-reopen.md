# 저장된 결과를 다시 열 때 현재 대운 표시

## 문제
- `calculateDaewoon`은 계산한 해(`currentYear`)를 기준으로 각 대운의 과거·현재·미래 구분을 결과에 고정한다.
- 브라우저(`localStorage`)나 계정에서 저장된 결과를 열면 대운표를 다시 계산하지 않는다. 그래서 Y년에 저장한 결과를 몇 해 뒤에 열면 대운 시간표의 ‘현재’ 표시·자동 펼침과 “{연도}년 기준” 문구, 기본 풀이의 지나온/지금/앞으로 문단, 인생 4계절의 현재 계절, 인생 그래프의 현재 위치와 메모 칸 이름이 저장한 해에 머문다.

## 요구사항
- 결과를 화면에 보여 줄 때 올해를 기준으로 각 대운의 과거·현재·미래 구분과 “{연도}년 기준” 문구를 다시 정한다.
- 저장 형식(`lib/saju/persistence.ts`, `lib/account/results.ts`)은 바꾸지 않는다. 기존 저장본을 그대로 열 수 있어야 한다.
- 대운 간지·시작/끝 연도·나이 등 사주·대운 계산은 바꾸지 않는다.
- 변경은 작게 유지한다.

## 구현
- `lib/saju/daewoon.ts`
  - `periodStatus(startYear, endYear, currentYear)`: 기존 `calculateDaewoon` 안의 과거·현재·미래 판정식을 그대로 옮긴 함수. `calculateDaewoon`도 이 함수를 사용하며 결과는 같다.
  - `timelineForYear(timeline, currentYear = 올해)`: 기간 정보는 그대로 두고 `status`와 `currentYear`만 다시 맞춘 대운표를 돌려준다. 바뀔 것이 없으면 같은 객체를 그대로 돌려주고, 입력 객체는 고치지 않는다.
- `app/saju-form.tsx`
  - `displayTimeline = timelineForYear(timeline, 올해)`를 만들어 화면과 화면용 계산(기본 풀이, 연운·월운 보고서, 인생 4계절, 인생 그래프, 만세력, 오늘의 운세, 운의 흐름, 대운 시간표)에 넘긴다. 오늘의 운세·연운·월운처럼 연도를 따로 받는 계산은 결과가 달라지지 않는다.
  - 브라우저 저장, 계정 저장(`cloudPayload`), AI 요청과 응답 처리에는 원래 `timeline`을 그대로 쓴다. 따라서 저장되는 자료는 이전과 같다.

## 검증
- [x] 구현 담당의 간단한 확인: 2015년 기준으로 계산한 대운표에 `timelineForYear(…, 2026)`을 적용한 결과가 2026년 기준으로 새로 계산한 대운표와 JSON으로 같다. 원래 객체의 기준 연도·현재 대운은 바뀌지 않았다(2015년, 2010년 시작 대운). 같은 해를 넣으면 같은 객체를 돌려준다.
- [x] `npm run check`: tests 282, pass 282, fail 0. `npm run build` 성공. `npx tsc --noEmit --noUnusedLocals` 오류 없음.
- [ ] 구현을 맡지 않은 서브에이전트의 테스트 작성·실행: 지난해 이전에 저장된 브라우저 저장본·계정 저장본을 열 때 현재 표시와 “{연도}년 기준” 문구, 저장 자료 불변, 새 계산 결과와의 일치, 경계 연도(대운 시작·끝 해), 대운 시작 전 구간.
- [ ] 실제 브라우저에서 예전 해에 저장된 결과를 열어 대운 시간표·인생 4계절·인생 그래프의 현재 표시 확인.

## 한계
- 기준 연도는 기존과 같이 이용자 기기의 현재 연도(`new Date().getFullYear()`)다.
- 저장된 Gemini 풀이는 다시 만들지 않는다. 풀이를 만든 연도와 선택 연도가 다르면 기존 안내(다른 연도나 이전 방식으로 작성됨)가 그대로 표시된다.
- 계정에서 연 결과의 ‘살펴볼 운의 연도’는 저장할 때 선택한 연도를 그대로 복원한다(기존 동작 유지).
