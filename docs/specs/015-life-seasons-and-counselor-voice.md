# 개인 대운 인생 그래프·4계절과 상담 말투

## 이용자 요청
- 8장 풀이를 실제 오랜 상담가와 마주 앉아 듣는 듯한 차분하고 정확한 말투로 쓴다. 강점과 함께 불편한 조건도 숨기지 않으며, 명리학을 모르는 이용자가 이해할 수 있어야 한다.
- 개인 사주의 대운 변화로 삶의 흐름을 그래프로 보고, 지금 어느 지점에 있는지와 4계절 중 어느 계절인지 해석한다.
- 이용자는 4계절을 나이 구간이 아닌 개인별 대운 변화에 따르도록 선택했다.

## 계산 기준
- 대운의 앞글자 천간과 아래글자 지지의 본기를 일간과 비교해 십성을 계산한다. 원국·출생지 보정·대운 시작 계산은 기존 엔진 그대로 사용한다.
- 계절은 **사건 예측이나 길흉 점수 아닌 삶의 주제**다. 앞글자 십성을 중심으로 인성·비견·겁재=봄(배움·내 기반), 식신·상관=여름(표현·실행), 편재·정재=가을(자원·결과), 편관·정관=겨울(책임·재정비)로 읽는다. 아래글자 본기의 계절이 다르면 함께 오는 주제로 표시한다. 계절은 반복되거나 순서를 건너뛸 수 있다.
- 그 대운의 기회·부담·행동·원국과의 합충은 기존 `analyzeFlow` 계산을 사용한다. 합을 무조건 좋게, 충을 무조건 나쁘게 취급하지 않는다. 계절별 의미를 건강·성과·사건의 확정 예언으로 바꾸지 않는다.
- 실제 현재 위치는 `timeline.currentYear`가 포함된 대운의 시작·끝을 이용해 연도 비율로 표시한다. 저장 당시의 기준 연도와 실제 오늘 연도가 다를 수 있으므로 표시 연도를 분명히 쓴다. 대운 시작 전이면 계절을 임의로 부여하지 않고 분류 전이라고 표시한다.
- 그래프 x축은 대운의 실제 시작 나이·연도, y축은 4계절의 **서로 다른 주제**다. 위아래는 운의 좋고 나쁨이나 행운 확률을 나타내지 않는다. 값이 없는 가상 점수·인구 백분율을 만들지 않는다.

## 화면
- 결과 페이지에 ‘나의 인생 4계절’ 그래프 추가. 현재 위치 점·세로선·범례·연도·나이·현재 계절을 함께 표시한다. 대운 카드와 상세 해석은 포인터/키보드 모두 선택할 수 있다.
- 선택한 대운의 앞글자와 아래글자, 계절 선정 이유, 기회·부담·현실 행동을 쉬운 한국어로 보여준다. 현재 대운의 연도 진행 위치와 당시의 대운/현재 선택한 대운을 구분한다.
- 모바일에서 전체 화면 가로 넘침 없이 읽고 그래프는 자체 스크롤 또는 축약형으로 본다. 선 외에 카드 텍스트로 모든 정보를 제공한다.
- 계산 근거·한계는 펼쳐 보기. 색 외에 계절 이름·현재 배지를 사용한다.

## 상담 문체
- 새 상담 문체 버전 3. 기존 버전 1/2 결과는 열 수 있고, 완성본에서도 새 문체로 다시 쓰는 버튼을 제공한다. 재작성 첫 성공 전 기존 자료를 유지한다. 검증/장별저장/기기·계정 정책은 그대로다.
- 생성 프롬프트는 ‘30년 상담 경력자의 설명 방식’을 요청한다. 서비스나 AI가 실제 사람/경력을 가졌다고 주장하지 않는다. 친근한 존댓말, 상담 자리의 대화감, 쉬운 생활말을 먼저 쓴다. 인상적인 말투만으로 빈약한 내용을 가리지 않는다.
- 각 절에는 개인별 계산 근거 둘 이상, 이 근거가 함께 작용하는 이유, 활용점, **불편하지만 확인해야 할 부담과 발생 조건**, 반대 근거, 가정 예시, 실제 경험 질문, 실행 가능한 선택을 넣는다. 장마다 일반론·칭찬·훈계만 반복하지 않는다. 한자 독음 병기, 용어 즉시 풀이. 과거 사건·미래 성과를 아는 척하지 않는다.
- 평생/전환기 장에는 4계절과 현재 위치의 계산 자료를 넣어 상담 풀이가 그래프와 같은 근거를 사용하게 한다. 원래 생년월일·도시·개인 질문은 Gemini에 보내지 않는다.
- Gemini가 현재·인접 계절을 누락하면 서버가 계산으로 확인된 계절 설명을 첫 절의 두 번째 문단에 보충한다. 현재 계절을 명시적으로 잘못 쓴 응답은 보충하지 않고 거부·한 번 재시도한다. 내용 소개로 끝나는 요약도 재작성을 요구한다.

## 검증
- 독립 담당 테스트: 일간/대운별 십성·계절, 앞·뒤 글자 다른 경우, 반복계절, 현재구간 경계와 시작 전, 두 사주의 차이, 그래프 카드 접근성/선택, 과거 저장 호환/재작성 경합, 프롬프트의 균형/쉬운말/4계절자료.
- 타입 검사, 전체 테스트, 빌드, 가상 입력 화면 및 실제 모델 샘플 확인. 개인 PDF·실제 사용자 출생정보 사용 금지.
- GitHub의 `feat/readable-manse-report` 브랜치와 PR #1만 갱신한다. `main`은 이용자가 추후 머지를 요청할 때 합친다.
