# 나의 대운, 나의 시간

[English](README.md) · **한국어**

생년월일·출생 시각·출생지를 입력하면 사주를 계산하고, 약 10년 단위의 흐름인 **대운**을 지나온 시간 → 지금 → 앞으로의 순서로 보여 주는 웹 서비스입니다.

서비스 주소: https://saju-service-steel.vercel.app

> 결과는 재미와 자기 성찰을 위한 참고 자료입니다. 의료·법률·투자 등 전문적인 조언이 아니며, 실제 사건을 예언하지 않습니다.

## 주요 기능

- **출생 정보 입력**: 양력 또는 음력 생일(윤달 포함. 윤달 여부를 모르면 가능한 두 날짜를 비교해 고를 수 있음), 출생 시각, 출생 국가와 도시. 도시의 시간대와 경도를 계산에 반영합니다. 1990년 이후 출생(음력은 1990~2100년)이고 출생 시각을 아는 경우를 지원합니다.
- **사주표**: 네 기둥의 한자·한글 독음·오행과 짧은 한마디. 한마디는 이미지 카드로 저장·공유할 수 있으며, 카드에는 출생 정보가 들어가지 않습니다.
- **결과 화면**: 오늘의 운세(매일 한국 시간 오전 9시 공개), 오행·십성, 균형·도움, 시기별 한 줄 메모를 적을 수 있는 인생 그래프, 인생 4계절, 운의 흐름(대운·연운·월운), 일·돈·관계·건강 등 생활 주제별 운.
- **귀인·신살**: 10가지 전통 표지를 누르면 내 사주에서의 뜻과 생활 실천을 보여 줍니다.
- **AI 풀이(서버 설정이 있을 때)**: 이미 계산된 사주 자료로 Google Gemini가 종합 풀이를 만듭니다. 짧은 핵심 풀이가 먼저 나오고 상세 풀이가 이어집니다. 실패하면 계산 결과는 그대로 두고 다시 시도 버튼을 보여 줍니다.
- **Google 로그인(선택)**: 결과를 계정에 저장하고 다른 기기에서 다시 엽니다.

## 개인정보

- 사주 계산은 이 프로젝트의 코드(`lib/saju`)가 직접 하며 AI에게 맡기지 않습니다.
- Gemini에는 계산된 사주 자료(기둥·오행·대운 등)만 보냅니다. 생년월일·출생 시각·출생 도시 원문은 Gemini에 보내지 않습니다. 이 안내는 제출 버튼 바로 앞에 표시됩니다.
- 로그인하지 않으면 마지막 결과(와 직접 적은 인생 그래프 메모)는 이 브라우저의 `localStorage`에만 남습니다.
- Google로 로그인하고 ‘계정에 저장’을 누르면 출생 입력·계산 결과·풀이가 Supabase에 저장됩니다. 데이터베이스의 행 단위 보안(RLS)으로 본인만 자기 기록을 읽고 저장하고 삭제할 수 있습니다.
- Gemini API 키는 서버에서만 사용하며 브라우저로 보내지 않습니다.

## 기술 스택

- Next.js 16(App Router), React 19, TypeScript
- 음력·사주 계산: `lunar-javascript`
- Google 로그인과 계정 저장: Supabase
- AI 풀이: Google Gemini(`@google/genai`), 서버 API 경로에서만 호출
- 배포: Vercel(매일 예약 작업이 오늘의 운세 공통 자료를 준비)

## 로컬에서 실행하기

Node.js 22.9 이상이 필요합니다.

```sh
npm ci          # package-lock.json에 적힌 버전 그대로 설치
npm run dev     # 개발 서버 실행 후 터미널에 표시된 주소 열기
npm run check   # 타입 검사와 전체 테스트
npm run build   # 배포용 빌드
```

환경변수가 하나도 없어도 서비스는 열립니다. 아래 표의 기능만 꺼집니다.

## 환경변수

`.env.example`을 `.env.local`로 복사해 필요한 값만 채웁니다. 실제 값은 Git에 올리지 않습니다.

| 변수 | 쓰는 곳 | 없을 때 |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Google 로그인과 계정 저장 | 로그인과 계정 저장·목록·열기·삭제가 동작하지 않습니다. 사주 계산과 브라우저 저장은 그대로 됩니다. |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Google 로그인과 계정 저장 | 위와 같습니다. |
| `GEMINI_API_KEY` | AI 풀이(서버 전용) | `/api/reading`이 오류 코드 `missing_api_key`와 함께 HTTP 503을 돌려줍니다. 계산된 사주와 기본 풀이는 그대로 볼 수 있습니다. |
| `CRON_SECRET` | 매일 예약 작업 경로 보호 | `/api/cron/daily`가 항상 HTTP 401을 돌려줍니다. 오늘의 운세는 방문할 때 계산됩니다. |
| `AI_RATE_LIMIT_WINDOW_SECONDS` | 선택. AI 요청 수를 세는 시간 창 | 600초(10분)를 씁니다. |
| `READING_RATE_LIMIT_PER_IP` | 선택. 시간 창 안에서 IP 하나가 보낼 수 있는 `/api/reading` 요청 수 | 6을 씁니다. 풀이 한 번에 요청 2건(짧은 요약 + 상세 풀이)을 쓰므로 풀이 약 3번입니다. |
| `READING_RATE_LIMIT_GLOBAL` | 선택. 시간 창 안에서 서버 인스턴스 하나가 받을 수 있는 `/api/reading` 요청 수 | 60을 씁니다. |
| `CONSULTATION_RATE_LIMIT_PER_IP` | 선택. 시간 창 안에서 IP 하나가 보낼 수 있는 `/api/consultation` 요청 수 | 3을 씁니다. 8장을 만드는 `scripts/verify-deep-consultation.ts`를 돌릴 때는 `.env.local`에서 10 정도로 올립니다. |
| `CONSULTATION_RATE_LIMIT_GLOBAL` | 선택. 시간 창 안에서 서버 인스턴스 하나가 받을 수 있는 `/api/consultation` 요청 수 | 20을 씁니다. |

제한값은 1 이상의 10진 정수(예: `10`)만 인정합니다. `1e1`, `0x10`, `5.0`, `0`, 음수 같은 값은 기본값으로 처리하고, 상한(시간 창 86400초, IP별 10000, 인스턴스 전체 100000)을 넘는 값은 상한으로 줄입니다.

### AI 요청 보호

Gemini를 부르는 두 경로(`/api/reading`, `/api/consultation`) 앞에는 다른 사람이 프로젝트의 Gemini 크레딧을 쉽게 쓰지 못하도록 간단한 보호 장치 두 가지가 있습니다.

- **같은 사이트 확인**: 다른 웹사이트의 브라우저가 보낸 요청은 HTTP 403(`forbidden_origin`)으로 막습니다. 이 사이트, Vercel 미리보기 주소, `localhost`에서 보낸 요청은 허용합니다. 브라우저 출처 정보가 전혀 없는 요청(예: `curl`, 스크립트)은 이 확인으로 막지 않으며, 아래 요청 수 제한만 적용됩니다.
- **요청 수 제한**: 입력 검사를 통과한 요청을 IP별, 서버 인스턴스별로 셉니다. 한도를 넘으면 Gemini를 부르기 전에 HTTP 429(`too_many_requests`)와 `Retry-After` 헤더를 돌려줍니다. 화면에는 풀이 대신 “요청이 많아 잠시 쉬어 갑니다. N분 뒤에 다시 시도해 주세요.”가 나오며, 지어낸 풀이를 보여 주지 않습니다.

이 숫자는 서버마다 메모리에서 따로 셉니다. Vercel은 서버를 여러 개 띄우거나 언제든 다시 시작할 수 있으므로 정확한 전체 한도가 아니라 최선 노력입니다. 전체 한도가 필요하면 프로젝트 소유자가 Vercel 대시보드의 Firewall에서 `/api/reading`, `/api/consultation`에 요청 수 제한 규칙을 추가해야 합니다.

## 폴더 구성

```text
├── app/                 화면: 입력, 결과 화면, 결과 메뉴, 계정 보관함
│   └── api/
│       ├── reading/       AI 풀이(Gemini, 서버 전용)
│       ├── daily/         오늘의 운세 공통 자료
│       ├── cron/daily/    매일 예약 작업(CRON_SECRET 필요)
│       ├── locations/     국가·도시 검색
│       └── consultation/  장별 상담 API(현재 화면에서는 쓰지 않음)
├── lib/
│   ├── saju/            사주 계산, 기본 풀이, AI 지시문과 응답 검사
│   ├── request-guard*.ts AI 경로의 같은 사이트 확인과 요청 수 제한
│   ├── account/         계정에 결과 저장·불러오기
│   └── supabase/        Supabase 브라우저 연결
├── supabase/migrations/ 데이터베이스 표와 본인 전용 접근 규칙
├── scripts/             수동 점검 스크립트(AI 풀이 표본, 계정 접근 규칙)와 도시 이름 자료 생성
├── tests/               자동 테스트
├── docs/                기획서(PRD), 기능별 Spec, 진행 상태
├── public/              이미지
└── AGENTS.md            이 저장소에서 일하는 AI 코딩 에이전트의 작업 원칙
```

## 작업 방식

1. 만들 것과 이유는 `docs/PRD.md`에 적습니다.
2. 변경마다 `docs/specs/`에 번호가 붙은 Spec(예: `045-maintenance-security-docs-a11y.md`)을 만들어 무엇을 하고 어떻게 확인할지 적습니다.
3. 그 Spec을 `docs/status.md`에 체크하지 않은 항목 `- [ ]`으로 추가합니다.
4. 구현 뒤 구현하지 않은 사람이 테스트를 작성·보강하고, 확인하지 못한 부분까지 포함해 결과를 Spec에 기록합니다.
5. 구현과 검증이 모두 끝난 뒤에만 `- [x]`로 바꿉니다.

변경 이력은 `CHANGELOG.md`에 있습니다.
